# dsh-skill-vault — DSH 技能库

把散落在各处的技能**只读**聚合成一份目录，按功能分类，提供「下载并入库」入口，
并在面板里实时显示已安装技能与正在下载的技能。

- 目标运行时：`@deepseek-ai/dsh` 0.2.x（0.2.1-rc.1 上核对过 API）
- 依赖：零。宿主半只用 `node:fs` / `node:path` / `node:os` / `node:zlib` / 内置 `fetch`
- 面板位：侧边栏「技能库」，main key = `skillvault`

## ★ 只读承诺（这是本插件的设计底线）

| 项 | 做法 |
|---|---|
| 读技能 | 只 `readdir` / `readFile` / `stat` / `cp`，源一侧永远只读 |
| 写技能 | **一行都没有**：不提供 delete / rename / 改 frontmatter 的端点 |
| 唯一写点 | `<DSH_HOME>/skill-library/`，每次写入前过 `assertInsideLibrary()` |
| 与 DSH 技能根的关系 | 库目录与 `~/.dsh/skills` **完全分离**，库里的东西不会自动加载，也不影响正在跑的技能 |
| 测试证据 | 宿主测试跑完比对全部源文件的 `sha256 + mtime`，断言完全未变（见 `tests/`） |

所以「安装」在本插件里的语义是：**把技能下载/复制进库**，不是往 DSH 技能根里塞东西。
想让某个技能真正生效，仍然由你自己决定（或继续用技能板那类工具）。

## 库目录长什么样

首次加载时自动创建（已存在则不动）：

```
<DSH_HOME>/skill-library/
├── README.md                 ← 根注释：每个分类目录的中文用途表
├── .library/categories.json  ← 机器可读的分类定义
├── 01-安全与逆向/
│   ├── _说明.md              ← 每个分类目录的中文注释
│   └── rev-demo/SKILL.md
├── 02-红队演练/
├── 03-成人写作/
├── 04-内容创作/
├── 05-浏览器与自动化/
├── 06-方法论与自进化/
├── 07-系统与排障/
├── 08-视觉与识图/
└── 99-未分类/
```

| 目录 | 用途 |
|---|---|
| 01-安全与逆向 | 逆向分析：静态/动态、脱壳、协议还原、保护对抗、证据链 |
| 02-红队演练 | 信息收集、漏洞扫描与利用、内网横向、隧道与代理、WebShell 工具 |
| 03-成人写作 | 成人向虚构叙事模板、世界观、分级描写参数库 |
| 04-内容创作 | 视频/图像生成流水线、Office 文档产物、PDF 处理 |
| 05-浏览器与自动化 | 浏览器操作、表单驱动、页面取证、截图 |
| 06-方法论与自进化 | 提示词内核、账本自进化、DSH 自身文档、预设构建 |
| 07-系统与排障 | 沙箱、权限、ACL、环境与进程诊断 |
| 08-视觉与识图 | 多模态识图、OCR、图表理解 |
| 99-未分类 | 未命中规则时落到这里，可按需在 `categories.json` 里加规则 |

分类判定顺序：**名字精确表 → 名字/描述正则 → 来源兜底（预设/插件根）→ 未分类**。

## 覆盖哪些技能

| 来源 | 说明 |
|---|---|
| `user-dsh` | `<DSH_HOME>/skills` |
| `user-agents` | `~/.agents/skills` |
| `project-dsh` / `project-agents` | 当前工作区的 `.dsh/skills`、`.agents/skills` |
| `preset:<名>` | `<DSH_HOME>/<预设>/skills`（如 reverse / redteam 预设根） |
| `plugin:<包>` | `profiles/*/node_modules/<pkg>/skills`（含 `@scope/pkg` 与 `skill/` 单数形态） |
| `builtin:app.asar` | 发行包内置：office ×4、diagnose-windows-sandbox-acl、dsh-doc |

`.disabled/` 里的技能也会列出来（标「已禁用」），重名会标「重名」，
frontmatter 不合规的会标「frontmatter 不合规」——**只标注，不改文件**。
内置（asar）与 frontmatter 不合规的技能标「内置不可收录」：可以看、可以进技能包清单，但不会去复制文件
（内置技能住在 `app.asar` 里，不合规的复制进库也加载不了）。

## 面板

| 区块 | 内容 |
|---|---|
| 顶栏 | 只读徽标、进行中任务数、刷新、下载并入库 |
| 统计行 | 总数 / 启用 / 库内 / 重名，加上库根与技能根的绝对路径 |
| 全部技能 | 按分类目录分组，**每个分类大标题就是折叠开关（▾ 展开 / ▸ 收起）**，标题栏带数量；搜索框右侧有「全部展开 / 全部收起」；每张卡显示名称、来源、标记、描述、路径，左侧复选框（含已入库的）+ 右侧「收录到库」 |
| 选择条 | 勾选 ≥1 个后出现：已选数量、技能包命名框、「收录所选」「存为技能包」「取消选择」；已选卡片上另有「取消选择」单条去掉；有已入库项被选中时提示「其中 n 个已入库，收录时自动跳过」；下方两行：**移到分类**（分类标题下拉 + 按钮，未入库的先收录、已入库的直接移动）与**插入到根**（技能根下拉 + 保留库内副本 + 插入按钮） |
| 我的库 | 库内已收纳技能，同样按分类分组；顶部有**分类标题管理**（新增自建标题 / 删除清空的自建标题），每张卡有分类下拉（改分类）与「移出库」 |
| 技能包 | 已保存的技能组合清单，一条命令「一键收录整包」 |
| 调用监控 | **大模型正在调用哪个技能**：进行中的调用实时显示（名称 + 已跑秒数 + 作用域/cwd），结束后变「完成/n 未命中/出错」，**60 秒后自动清理**；顶部「调用中 n · 记录 m」 |
| 下载任务 | 实时任务列表（SSE 推送）：状态、阶段、字节数、进度条、子项 n/m、失败子项明细；运行中带「取消」，结束后带「重跑未完成」「移除记录」；顶部有「清除已完成 (n)」「完成后自动清除记录」「**允许写入技能根**（默认关）」「操作日志」 |
| 安装弹窗 | URL（.zip / .tar.gz / .md）或本地路径 + 可选重命名 + 可选分类 |

任务轮询 1.2 秒一次；任务从「进行中」变为「完成」时自动刷新目录并弹提示。

## 一个任务要用多个技能怎么办

技能本身在 DSH 里是**按需加载**的（模型用 `skill` 工具逐个取），所以「同时用几个」不需要提前入库。
但如果你想把一组技能当成一个**可复用的组合**（换机器、给别人、下次一秒钟备齐），用这两条：

1. **多选 + 收录所选**：勾上任意几个 → 「收录所选」→ 一个批量任务串行收录，任务里逐条显示成功/失败。
2. **技能包**：勾选后填个名字 → 「存为技能包」→ 写到
   `<库根>/.library/bundles/<名字>.json`（含 name / source / path / category）→
   以后在「技能包」tab 点「一键收录整包」即可整组入库；换机器把这个 json 复制过去也能用。

批量与整包都走同一个任务队列，**源技能依旧只读**；库里已有同名的会被单独标失败，其它继续跑，不会中断整批。

### 分类折叠（v1.7.0）

- 点任意分类大标题 = 收起/展开该组，标题左侧的 `▾ / ▸` 指示当前状态，右侧文字提示「收起 / 展开」
- 搜索框右边「全部展开」「全部收起」一键处理所有已渲染的分组
- 折叠只影响显示，不影响勾选：已勾选的技能在被收起的组里依然是选中状态，批量收录/存包会照常带上
- 「我的库」tab 用同一套折叠状态

### 勾选规则（v1.3.1）

| 卡片状态 | 有复选框？ | 「收录所选」时的行为 |
|---|---|---|
| 未入库、可收录 | ✅ | 复制进库 |
| **已入库** | ✅（**绿标「已入库」本身也可点，等于勾选/取消**） | 自动跳过，并在选择条提示 |
| 内置（asar）/ frontmatter 不合规 | ❌ | 不可收录，只有「内置不可收录」标注 |

只选了已入库的项时，「收录所选」不会发请求，只提示「所选的 n 个技能都已在库里……（可以「存为技能包」）」。

### 插入到根（剪切 / 复制，v1.9.0）

库里的技能（包括「我的库」里的每一张卡，以及「全部技能」里已入库的那些）**都能勾选**，
勾上之后在操作条里选一个技能根，点「插入到根」就像剪切粘贴：

| 选项 | 行为 |
|---|---|
| 目标根下拉 | 只列**可写根**：`user-dsh`、`user-agents`、`project-dsh`、`project-agents`、`preset:<名>`；`plugin:*` 与 `app.asar` 内置不出现在下拉里 |
| 「保留库内副本」不勾（默认） | **剪切**：库内副本搬到该根（跨盘自动退化成复制+删除） |
| 「保留库内副本」勾上 | **复制**：根里多一份，库里保留 |
| 目标根已有同名 | 409，绝不覆盖 |
| 名字里带 `..` / 分隔符 | 400 |
| 源不在库里 | 400（只有库内副本能被搬运） |

插入后若该技能就在 DSH 的用户根里，它会立刻出现在「全部技能」中并且可以直接被 `skill` 工具加载；
库里的状态随之变化（剪切时这条会消失，复制时 `已入库` 仍在）。

### 在「全部技能」里像剪切一样移到分类（v2.1.0）

勾上任意技能（不必先收录），选择条里选一个**分类标题**（`01-安全与逆向`、`我的常用`…），点「移到分类」：

| 选中项状态 | 实际动作 |
|---|---|
| 还没入库（来自某个根/插件/内置之外的可复制来源） | 先按源路径**收录**进库，直接落到该分类 |
| 已经在库里 | 库内副本**移动**到该分类（等同改分类） |
| 分类里已有同名 | 那条报 409，其余继续，最后在错误条列出失败项 |

这就是"剪切"效果：`全部技能` 里勾 → 选分类 → 一步到位，不用先去「我的库」再拖。
自建标题同样可作目标；未指定分类时才走自动分类规则。

### 分类标题（v2.0.0）

「我的库」顶部的「分类标题」区就是库的目录结构，标题 = 目录名：

| 操作 | 规则 |
|---|---|
| 新增标题 | 输入名字即可（≤40 字，不能含 `\\ / : * ? " < > |` 或 `..`）；会立刻建目录 + 补 `_说明.md` |
| 删除标题 | **只有自建的、且下面已清空**的标题能删；内置 9 个分类不给删（怕和库骨架冲突） |
| 重名 | 409；空名 400 |
| 选择器外观 | 全站下拉统一深色：黑底 `#1b1b1b` + 白字 `#e9e9e9` |

「插入到根」的技能根下拉也不再显示路径串，而是显示**大标题**：
`用户技能根` / `用户 agents 根` / `当前项目技能根` / `当前项目 agents 根` / `预设「reverse」`，
鼠标悬停仍可看到真实路径（`title` 属性）。

### 改分类（v1.8.0）

「我的库」每张卡片右侧有一个分类下拉：

| 操作 | 结果 |
|---|---|
| 选另一个分类目录 | 该库内副本被 `rename` 到 `<库根>/<新分类>/<名>`，卡片立刻出现在新分组里 |
| 选回当前分类 | 什么都不做（noop） |
| 目标分类已有同名 | 409，不覆盖；请先给其中一个改名或移出 |
| 分类名里带 `..` / 路径分隔符 | 400，只接受已登记的 9 个分类名 |
| 想新建分类 | 在 `<库根>` 下建目录，或用「下载并入库」时指定分类；插件只认已存在的目录 |

改分类只动库内副本，源技能依旧只读；`_说明.md` 若缺失会自动补一份。

### 移出库（把我的库里的东西请出去）

| 想做什么 | 操作 |
|---|---|
| 把库内某个技能移出 | 「我的库」tab → 卡片右侧「移出库」→ 确认 |
| 移出之后 | 「全部技能」里该技能最右侧**自动回到「收录到库」**，可以随时再收回来 |
| 彻底删源技能 | 本插件永远不碰源技能；要删请自己处理 `~/.dsh/skills` 或对应预设根 |

移出**只删库内副本**（`<库根>/<分类>/<名>`），DSH 技能根里的原件一个字节都不动；
没有回收区、没有中间态，删完即回到未收录状态。
（1.4.x 的 `/takeout` 端点保留为别名，语义同样变成"删除库内副本"，旧前端不会报错。）


### 安全开关 · 审计 · 撤销（v3.0.0）

| 机制 | 说明 |
|---|---|
| **允许写入技能根**（默认关） | 关着的时候 `POST /paste` 直接 403；要往 `~/.dsh/skills` 这类根里放东西必须先在「下载任务」页勾上 |
| **操作日志** | 所有写操作（移出库 / 改分类 / 剪切到根 / 删分类 / 改设置 / 撤销）追加到 `<库根>/.library/audit.log`；面板点「操作日志」可看最近 50 条 |
| **撤销栈（10 分钟）** | 移出库的内容先挪进 `.library/undo-bin/`；改分类、剪切到根也都会入栈。顶部出现「撤销上一步」，`GET /undo` / `POST /undo` 可查可撤；超过 10 分钟自动清理并真删 |
| 撤销边界 | 撤销「剪切到根」= 把文件搬回库；撤销「改分类」= 搬回原分类；撤销「复制到根」= 删掉根里那份新拷贝；原位被占用时 409 不覆盖 |

### 实时推送（v3.0.0）

`GET /skill-vault/stream` 是一条 `text/event-stream` 长连接，每秒推一帧
`{ tasks, invocations }`。面板优先用 `EventSource`，环境里没有（或连接失败）就自动退回 1.2 秒轮询——
两种模式 UI 完全一致，测试跑的是轮询分支。

### 调用监控（v2.2.0）


面板新增大项「调用监控」。实现方式是**挂钩技能注册表**：模型通过 `skill` 工具加载技能体时会走
`skills.get(name)`，插件在这层包一个计时器：

| 状态 | 面板表现 |
|---|---|
| 正在调用 | 「调用中」黄标 + 名称 + `已跑 4.2s`，每 1.2 秒刷新一次（真的在动） |
| 调用结束 | 变绿「完成」/ 灰「未命中」/ 红「出错」，显示耗时 |
| 结束超过 60 秒 | **自动从列表消失**（`recent` 只保留 60 秒内的，最多 60 条） |
| 顶部统计 | `调用中 n · 记录 m`，还带 `stats.byName` 每个技能的累计次数 |

注意：这里统计的是"技能被加载"这一动作，不是每次 `skill` 工具调用的参数；插件只读这一个入口，
不窥探你的会话内容。`ctx.effect` 卸载时会还原 `registry.get`，不给宿主留钩子。

### 任务记录留不留，由你决定

| 你的选择 | 怎么做 |
|---|---|
| 想留记录（默认） | 什么都不用做；任务卡右侧有「移除记录」，想清一条点一条 |
| 一次清掉所有已结束的 | 任务页顶部「清除已完成 (n)」 |
| 完成后自动不留记录 | 勾选任务页顶部的「完成后自动清除记录」——之后任务一结束记录立刻消失 |
| 还想再跑一次却删了记录 | 记录删了就没了（重跑按钮在记录上）；需要的话先别删，或重新发起下载/收录 |

开关状态存在 `<库根>/.library/settings.json`，跟库一起走；运行中的任务不能删记录（先取消或等它跑完）。

### 取消

| 想取消什么 | 操作 |
|---|---|
| 取消单个已勾选的技能 | 卡片右侧「取消选择」，或再点一次复选框 |
| 取消全部勾选 | 选择条上的「取消选择」 |
| 取消正在跑的任务 | 「下载任务」tab 里任务卡右侧「取消」 |
| 取消整批收录 | 同上（批量任务就是一个任务，取消后已完成的子项保留，剩余标 `skipped / 已取消`） |

### 续跑（取消 / 失败之后想继续）

| 想做什么 | 操作 |
|---|---|
| 把取消掉的批量任务里剩下的补完 | 任务卡右侧「重跑未完成」→ `POST /tasks/retry { id }` |
| 失败的下次再试一次 | 同上（失败的下载、整批都能重跑） |
| 整批推倒重来 | `POST /tasks/retry { id, all: true }` |

续跑会建一个**新任务**，标签带「（续跑 n）」，只包含原任务里 `status !== done` 的子项；
已完成的不重复复制（否则会 409）。原任务记录保留在列表里可查。

取消语义：排队中 → 立刻 `canceled`；运行中 → 置 `cancelRequested`，任务在下一个检查点（每个子项开始前 / 每次下载分片后）停下，状态变 `canceled`，半截临时文件在收尾时清掉。

## HTTP 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/skill-vault/ping` | 版本、库根、技能根、asar 位置、只读标记 |
| GET | `/skill-vault/catalog?refresh=1` | 全部技能 + 库 + 分类 + 来源根 + 统计 |
| GET | `/skill-vault/library` | 库内条目 |
| GET | `/skill-vault/tasks` | 任务列表（前端轮询） |
| GET | `/skill-vault/invocations` | 当前/最近技能调用（`active` / `recent` / `stats.byName`，含 `scope`/`cwd`）+ 60 秒 TTL |
| GET | `/skill-vault/stream` | SSE 长连接：每秒推一次 `{ tasks, invocations }` |
| GET | `/skill-vault/audit` | 审计日志（最近 N 条，`?limit=` 上限 500） |
| GET/POST | `/skill-vault/undo` | 撤销栈查询 / 执行撤销（`{ id? }`，10 分钟窗口） |
| POST | `/skill-vault/download` | `{ url?, path?, name?, category? }` → 建任务 |
| POST | `/skill-vault/harvest` | `{ skillPath, name?, category? }` → 复制进库 |
| POST | `/skill-vault/harvest-batch` | `{ items?, names?, bundle? }` → 批量收录（子项状态逐条回报） |
| POST | `/skill-vault/tasks/cancel` | `{ id }` → 取消任务：排队中立即取消，运行中在下一个检查点停下 |
| POST | `/skill-vault/tasks/retry` | `{ id, all? }` → 续跑：只补没成功的子项（`all:true` 则整批重来） |
| POST | `/skill-vault/tasks/clear` | `{ ids? }` → 删除任务记录：给 ids 只删指定几条，不给就清掉全部已结束的；还有在跑的会 409 |
| GET/POST | `/skill-vault/settings` | `{ autoClearTasks? }` → 完成后是否自动删除记录（存 `<库根>/.library/settings.json`） |
| GET | `/skill-vault/bundles` | 列出已保存的技能包 |
| POST | `/skill-vault/bundles` | `{ name, note?, items[] }` → 保存技能包清单 |
| POST | `/skill-vault/paste` | `{ path, root, name?, copy? }` → 把库内副本剪切/复制进某个可写技能根（同名 409） |
| POST | `/skill-vault/categories` | `{ dir, note? }` → 新增自建分类标题（重名 409） |
| POST | `/skill-vault/categories/remove` | `{ dir }` → 只删「自建 + 已清空」的标题（内置 400、非空 409） |
| POST | `/skill-vault/move` | `{ path \| name+categoryDir, toCategoryDir }` → 把库内副本挪到另一个分类（同名 409、非法名 400） |
| POST | `/skill-vault/remove` | `{ path \| name+categoryDir }` → 删除库内副本（源技能不动）；删完该技能回到「收录到库」 |
| POST | `/skill-vault/takeout` | 兼容旧客户端的别名，语义同 `/remove`（返回里带 `deprecated`） |
| GET | `/skill-vault/reveal?dir=` | 返回库内目录的绝对路径（拒绝越界） |

同源三重校验（`sec-fetch-site` / `origin` / `Host`）、请求体上限 1 MiB、
所有写入必须落在库根内、`harvest` 拒绝从库内再收录。

## 安装

```powershell
dsh-skill-vault\install.cmd
# 或： powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

脚本会：复制到 `%USERPROFILE%\.dsh\plugins\dsh-skill-vault` → 在 profile `package.json` 登记

卸载：`dsh-skill-vault\uninstall.cmd`（移登记项 + 删插件目录；**库目录保留**，可手动删）。

## 故障排查

| 现象 | 原因 | 处置 |
|---|---|---|
| 点某个按钮报 `响应不是 JSON（HTTP 405）` 或 `宿主缺少这个端点（HTTP 405）` | **面板是新的、宿主半还是旧版本**：DSH 启动时把 `lib/index.js` 载入内存，之后改盘不会热更；而页面刷新会重新拉 `client.js` | 重启 DeepSeek Harness。1.4.1 起面板会在版本不一致时于顶部显示黄色提示 |
| 启动报 `cannot resolve profile bundle "dsh-skill-vault"` | profile 登记了但 `node_modules` 里没有 | 在 profile 目录跑 `pnpm install`，或重跑 `install.cmd`（脚本会自校验链接） |
| 面板里技能列表是空的 | `DSH_HOME` 指到了别处，或技能根本不存在 | `GET /skill-vault/ping` 看 `dshHome` / `skillsRoot` 是否符合预期 |
| 收录报 `frontmatter 不合规` | 源技能缺 `description` 或 name 不是 kebab-case | 这是 DSH 官方口径，插件不会替你改文件 |



- 内置（asar）技能只做展示；`harvest` 一个内置技能是否成功取决于宿主进程能否读 asar 内的文件，读不到会返回明确错误，不会写坏任何东西。
- 内置清单是静态表（office ×4 / diagnose / dsh-doc），DSH 升级新增内置技能时需要同步这张表。
- `browser-demo` 这类"由插件代码注册、磁盘上没有 frontmatter"的技能会显示「frontmatter 不合规」，但依然能被收录（复制文件本身成功）——这是标注，不是拦截。
- 库只做收纳，不做版本管理；重复收录同名技能会返回 409 而不是覆盖。

## 已知边界

- 只管理用户根与 `DSH_SKILL_BOARD_ROOTS`… 见上（本插件用 `DSH_HOME`）；项目根与 preset 内置技能按 cwd 动态解析，不在面板范围内。
- 内置（asar）技能只展示、不可复制；内置清单是静态表，DSH 升级新增内置技能需同步。
- 库只做收纳，不做版本管理；同名重复收录返回 409 而不是覆盖。
- 移出库是直接删除库内副本（无回收区）；源技能始终只读。
